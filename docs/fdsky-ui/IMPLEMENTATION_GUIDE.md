# Инструкция разработчику: Heltec V4 companion OLED

## Цель и порядок

Работать только над компаньоном Heltec WiFi LoRa 32 V4, OLED 128×64 и одной кнопкой. Репитер — другая ветка и сборка. Код из PR #1 (ADC, проценты, заставка by FDSKY) и PR #2 (заголовок и базовая навигация) уже включён в `main`. Макеты в этом каталоге — целевой UX, не доказательство уже реализованных функций.

1. Сверить каждый экран с [каталогом](SCREEN_CATALOG.md), реальными полями prefs и доступностью оборудования. Не зашивать демонстрационные значения.
2. Убрать однотипную нижнюю подсказку из рендера OLED companion: освободить y=50…63 для четвёртой строки данных. Предусмотреть длинные надписи и не перекрывать заголовок с процентом/номером страницы.
3. Вывести достоверные состояния BLE, Wi-Fi (SSID, IP и отдельно клиенты 5000/5001) и USB. Порт 5001 не доказывает, что клиент — Home Assistant; без детектора USB-клиента показывать «неизвестно».
4. На радио показать фактические FQ/BW/SF/CR/TX, текущий профиль, факт companion repeat и внешний FEM LNA. RX Boost SX1262 — отдельный параметр. Если `canControlLoRaFemLna()` ложен, не показывать рабочий переключатель LNA. Перед применением профиля показывать параметры и repeat; после применения читать действительные prefs и состояние ограничения по частоте.
5. Для питания показывать «сон CPU разрешён/недоступен», а не «CPU выключен» во время работы UI. Отдельно RX Boost, FEM LNA, блокировку сна при BLE/Wi-Fi/GPS. Изменения с риском потери связи подтверждать; «Отмена» по умолчанию.
6. Сохранить остальные сценарии: сообщения и локальные счётчики, объявления/соседей, шум/сканирование с восстановлением исходного радио, GPS/маяк, условные датчики, OLED-время, звук при наличии buzzer, подтверждение выключения и CLI rescue.

## Однокнопочное управление

| Жест | Обычное действие | В контекстах |
|---|---|---|
| 1 клик | Следующий экран/пункт | В списке выбирает строку; в редакторе меняет цифру |
| 2 клика | Назад/отмена | Возврат из подэкрана без побочного переключения |
| Удержание | Открыть/подтвердить | На экране соединений переключить выбранный интерфейс |
| 3 клика | Только явно подписанное контекстное действие | Существующий профиль радио или звук не должен потеряться |
| 4 клика | Маяк, если поддержан | Не назначать общую навигацию |

Первый **завершённый жест** после погасшего OLED только будит экран. Долгое нажатие в первые 8 секунд загрузки остаётся доступом к CLI rescue. Если контексту нужен другой смысл жеста, он должен быть объяснён в меню действий или краткой подсказке именно на этом экране. Все изменения радио, соединений и питания показывать перед применением; «Отмена» предвыбрана.

## Точность данных и проверка

- Заряд: текст `86%` или `--%`, без иконки. Калибровка ADC правит напряжение и хранится в prefs; процент по напряжению не равен измеренной ёмкости. USB не доказывает полный заряд.
- LNA: наличие проверять аппаратной способностью, а статус брать с платы; не смешивать с RX Boost. Профили Long/HiNoise могут включать companion repeat только на разрешённой частоте.
- Сканирование: отмена и завершение должны восстановить параметры радио; лучшая частота не применяется автоматически.
- GPS/маяк: различать модуль, питание, fix, спутники, координаты и ожидание. «Отправлено» не означает «доставлено».
- Проверить сборку целевой конфигурации, затем живой Heltec V4: 1/2/3/4 клика, удержание, пробуждение, BLE/Wi-Fi/USB, отсутствие и наличие управляемого FEM, ADC после перезагрузки, отсутствие наложений текста. Сборка не заменяет проверки на плате.

Каталог содержит 140 состояний, а не 140 отдельных обязательных страниц прошивки: многие — варианты одного и того же экрана, ошибки или диалоги. Реализацию можно вести малыми PR по функциям.
