# Пиксельный аудит OLED 128×64

Изменения относятся к компаньону Heltec V4. Это аудит координат кода и проверки на хосте, не фотографии новой прошивки. Полная сборка и визуальная приёмка на плате ещё нужны.

## Сетка

Координаты областей ниже полуоткрытые, правая граница не включается.

| Элемент | Геометрия |
|---|---|
| Основной текст | x ∈ [3,125), ширина 122, минимум 3 px до боковых краёв |
| Шапка | y ∈ [0,12), курсор текста y=2, кириллическая ячейка y=1…10 |
| Заголовок с часами | x=3, до x=65; часы заканчиваются на x=98; резерв заряда до x=125 |
| Вложенный заголовок | префикс `./`, затем название; процент без иконки |
| Обычные четыре строки | курсор y=18,29,40,51; шаг 11 px для ячейки высотой 10 px |
| Две независимые колонки | [3,63) и [65,125), по 60 px, зазор 2 px |
| Таблица связи | названия x=3, состояния [36,69), клиент [72,125) |
| Маркер и название | маркер x=3, название x=12, зазор 3 px после 6px маркера |
| Строки выделенного меню | текст x=4, справа поле 4 px, заливка на всю ширину |
| Радиопараметры | рамка x=3,y=36,122×12; текст ограничен внутренней шириной |
| История NF | рамка x=74,y=50,51×11; между рамками две пустые строки пикселей |

Выравнивание задаётся областями и фактической шириной шрифта, не пробелами. Подписи слева, независимые значения справа. Длинные имена сокращаются с многоточием по границе своей области. Пары «подпись/значение» с переменной длиной числа резервируют ширину значения и зазор 3 px. Крупная частота, графики, редактор АЦП и диалоги имеют собственные координаты, их не следует механически сдвигать на обычную сетку.

## Пройденные группы экранов

| Группа | Результат проверки кода |
|---|---|
| Главная, счётчики сообщений | общий шаг строк 11 px, сокращение длинных строк |
| Радио и параметры | защищены две колонки, компактный RPT, текст внутри рамки, разнесены рамки параметров/NF |
| Шум и поиск частот | боковые поля графиков; исправлен x рамки и заполнения поиска частот |
| GPS | строки SAT/ALT/LAT/LON согласованы с сеткой; высота и скорость разделены по ширине; скорость пока прочерк |
| Связь и управление интерфейсами | ограничены три колонки, значения переключателей выровнены справа |
| Маяк и выбор получателя/интервала | режим и интервал разделены, подсказки пустых списков ограничены по ширине |
| Недавние и соседи | имя ограничивается доступной шириной, возраст/SNR выровнены справа |
| Датчики | подпись ограничена шириной числового значения; шаг строк 11 px |
| Время, узлы времени, контакты | колонки часового пояса/языка; маркер отделён от имени; нижняя подсказка отделена от счётчика |
| Настройки, язык, питание | единый шаг строк, резерв ширины значения, отдельные области режима и состояния сна/RX/LNA |
| Батарея и АЦП | сохранена связь указателя цифры с редактируемым значением; списки/подтверждение в пределах полей |
| Сведения и загрузка | длинная версия прошивки сокращается; подпись `by FDSKY` сохранена |
| Локальные сообщения и диалоги | сохранены ограниченные по ширине строки и перенос текста; входящие не переключают экран |

Фоновая заливка, выделение и логотип могут доходить до края. Для текста это не используется. Сокращение не меняет хранимое имя или значение.

## NF каждые 500 мс

Изменены период перерисовки радио и добавления точки истории. В целевой сборке `heltec_v4_oled_companion_usb_ble_wifi` также задан `NOISE_FLOOR_CALIB_INTERVAL=500`, иначе новые цифры продолжали бы появляться лишь после штатного двухсекундного цикла.

Сохранено усреднение 64 допустимых отсчётов. Приёмник не измеряет шум во время приёма пакета и не начинает новый цикл, пока старый не завершён. Поэтому 500 мс — целевой период, не гарантия свежего измерения в занятом эфире. История из 12 точек соответствует примерно 6 секундам. После смены радиопараметров сохраняется двухсекундный период ожидания. Настройки репитера не менялись.

## Возврат на главную

Четыре быстрых нажатия уже реализованы. Обработчик действует независимо от открытого окна, очищает вложенность и незавершённые подтверждения, закрывает редактор АЦП и вызывает остановку поиска с восстановлением радио. На выключенном экране первый законченный жест только включает дисплей. Входящие сохраняются без открытия просмотра.

## Проверки и задание Иосифу

`python3 scripts/check_v4_pixel_layout.py` компилирует извлечённые из текущего исходника функции размещения текста и возврата на главную. Используются реальный DisplayDriver с многоточием, таблица ширин кириллицы и реальный MomentaryButton. Проверяются длинные RU/EN строки, отсутствие пересечения колонок, поля, четыре строки, сброс состояний меню и события 1/2/3/4 кликов. Проверка проходит с `HELTEC_LORA_V4` и без него. Дополнительно проверены три настройки периода NF и `git diff --check`.

Это не проверка всех ветвей полного render() и не сборка ESP32. Иосифу нужно взять актуальный SHA PR №9, выполнить `pio run -e heltec_v4_oled_companion_usb_ble_wifi`, прошить и приложить результат с SHA.

На плате проверить RU/EN, 100% и прочерки заряда, длинные имена, максимальные значения полей и нижние строки. Снять главную, радио, GPS, связь, питание, настройки, сообщения и АЦП. Проверить четыре клика из текста сообщения, вложенного меню, подтверждения, редактора АЦП и активного поиска. Во время приёма сообщений меню должно оставаться открытым. Сравнить NF в тихом и занятом эфире, отзывчивость кнопки и приём пакетов после ускорения обновления.
