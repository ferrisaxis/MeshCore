# MeshCore Companion — спецификация дисплея и управления (для UX-ревью)

## 1. Железо и ограничения

- Устройство: **Heltec WiFi LoRa 32 V4** (ESP32-S3, 16 МБ flash, 2 МБ PSRAM, LoRa SX1262, FEM).
- Дисплей: **OLED 128×64**, монохромный (SSD1306), 1 бит на пиксель, без градаций серого.
- Управление: **одна физическая кнопка** (GPIO0, активный уровень LOW). Джойстика, энкодера, тача — нет.
- Прошивка: форк MeshCore «companion radio» (устройство-компаньон к телефону), плюс Wi-Fi и USB.

### Шрифты и метрики (жёсткие ограничения вёрстки)

| Элемент | Размер |
|---|---|
| Заголовок (title bar) | полоса 128×12 px: слева имя ноды, справа иконка батареи |
| Индикатор страниц | точки на y=14 (2×2 px, активная 4×4 px), по центру |
| Рабочая область | y = 18…63 → **46 px высоты** |
| Текст size 1 | 6×8 px на символ → **21 символ в строке**, строк с шагом 10–12 px |
| Текст size 2 | 12×16 px на символ → **10 символов в строке** |
| Максимум строк на экране | 4 строки size 1 (шаг 12) или 2 строки size 2 |

Цвета: только 2 (пиксель вкл/выкл). В коде есть роли: `primary_txt`, `secondary_txt`, `warning_txt`, `title_bkg`, `corp_blue` — фактически это «белый» и «чёрный», контраст достигается инверсией.

## 2. Модель ввода (одна кнопка)

Распознавание жестов на плате: long press = **1000 мс**, окно мультиклика = **280 мс**.

| Жест | Событие в коде | Примечание |
|---|---|---|
| 1 клик | `KEY_NEXT` | основная навигация «вперёд» |
| 2 клика | `KEY_PREV` (через обработчик double) | «назад» |
| 3 клика | `KEY_SELECT` | контекстное действие экрана |
| 4 клика | `KEY_QUAD` | только для маяка |
| Долгое нажатие (≥1 с) | `KEY_ENTER` (через long-press) | контекстное действие экрана |

Важно: **первый клик одиночного нажатия срабатывает только через 280 мс** после отпускания — экран не должен выглядеть «залипшим».

Отдельно: **долгое нажатие в первые 8 секунд после включения** уводит в аварийный CLI (service mode) — это не пользовательская функция, но конфликтует с «долгим нажатием = действие» на стартовом экране.

## 3. Структура навигации

Линейный список экранов, листается по кругу: **1 клик — вперёд, 2 клика — назад**. Индикатор из точек показывает позицию.

Порядок экранов (в этой сборке):

```
1  FIRST        — главный экран
2  RECENT       — недавно слышанные ноды
3  NEIGHBORS    — соседи (0-hop)
4  RADIO        — параметры радио
5  POWER        — энергосбережение
6  SCAN         — шум/уровень сигнала
7  FSCAN        — поиск свободной частоты
8  BLUETOOTH    — статус интерфейсов + PIN
9  GPS          — состояние GPS
10 BEACON       — маяк (только если GPS включён)
11 SETUP        — настройки (Clock; на e-ink ещё ScreenMode)
12 SHUTDOWN     — выключение
```

Плюс один **скрытый подэкран**, не участвующий в листании:

```
8 BLUETOOTH —долгое нажатие→ CONNECTIONS (выбор/переключение интерфейсов) —долгое нажатие→ назад
```

Скрытые/условные экраны: `BEACON` виден только при включённом GPS; `SETUP` на OLED показывает одну строку, на e-ink две.

## 4. Экраны: содержимое и действия

### 1. FIRST (главный)
Назначение: состояние связи с телефоном, счётчик сообщений, время.

Содержимое:
```
[имя ноды]                          [батарея]   ← title bar
              • • • • • •                         ← точки страниц, y=14

              MSG 3/5                             ← size 2, y=20 (отправлено/в очереди)
             192.168.1.42                         ← size 1, y=43: IP если телефон подключён
             Pin:123456                           ← size 1, y=43: PIN если не подключён
          14:32   Чт 05.11                        ← size 1, y=53: время и дата
```
Поведение:
- если телефон/клиент подключён — в средней строке **IP-адрес** Wi-Fi;
- если не подключён — **PIN** для сопряжения;
- клик / двойной клик — листание;
- **долгое нажатие — открыть превью последнего сообщения** (если оно было закрыто).

### 2. RECENT (недавние)
Список нод, от которых были advert-пакеты. Формат строки: `Имя......  12m` (время: `45s`, `12m`, `3h`).
- до 5 строк, шаг 11 px, имя обрезается по ширине;
- пусто → по центру «no adverts» + подсказка «advert: hold»;
- **долгое нажатие — отправить advert** (широковещательный пакет «я здесь»), всплывает «Advert sent!».

### 3. NEIGHBORS (соседи)
Список прямых соседей: `Имя......  +7` (SNR в дБ).
- при переполнении список **сам прокручивается** по таймеру;
- пусто → «no neighbors» + подсказка «poll: hold»;
- **долгое нажатие — опрос соседей** («Polling...»).

### 4. RADIO (радио)
```
FQ: 868.731   SF: 7        ← частота и spreading factor
BW: 62.50     CR: 7        ← полоса и coding rate
TX: 10dBm  LNA: on         ← мощность; LNA только если плата умеет
LongFast            3x: profile   ← текущий профиль; 3 клика — следующий
```
- **3 клика — сменить радио-профиль** (набор предустановок), всплывает имя профиля;
- **долгое нажатие — вкл/выкл LNA** (усилитель приёма FEM), только если плата поддерживает.

### 5. POWER (энергосбережение)
```
Power                       Eco max
CPU on                  RX on
LNA on                             ← только если есть FEM
              mode: hold
```
- строка 1: имя текущего профиля питания;
- строка 2: состояние CPU sleep и RX boost;
- строка 3: LNA (если есть);
- внизу подсказка или предупреждение «GPS needs CPU on» / «BLE needs CPU on», если профиль упирается в занятый ресурс;
- **долгое нажатие — следующий профиль питания** (циклически, всплывает имя).

### 6. SCAN (шум)
```
                  -97          ← size 2: текущий уровень RSSI
NL -105            pk -89      ← шумовой пол и пик; справа «PKT» при приёме пакета
[███████░░░░░░░░░░░░░░░░░]     ← шкала -120…-50 dBm
```
- экран обновляется автоматически;
- **долгое нажатие — сброс пика**.

### 7. FSCAN (поиск частоты)
Три состояния:
- простой: «find quiet freq» + «scan: hold»;
- скан: «scan 12/48», текущая частота, прогресс-бар;
- готово: «now 868.731» и топ-3 частоты с RSSI, текущая помечена `*`.
- **долгое нажатие — запуск сканирования**.

### 8. BLUETOOTH (статус интерфейсов)
```
BLE   ON
WiFi  OFF
USB   ON
Pin:123456
```
- строки статуса трёх интерфейсов (без иконки);
- PIN мелким шрифтом ниже;
- листание: 1 клик вперёд / 2 назад;
- **долгое нажатие — войти в подэкран CONNECTIONS**.

### 8a. CONNECTIONS (подэкран: выбор и переключение)
```
>BLE   ON
 WiFi  OFF
 USB   ON
```
- маркер `>` у выбранной строки;
- **1 клик — маркер на следующую строку** (BLE → WiFi → USB → BLE), страница НЕ листается;
- **2 клика — вкл/выкл выбранный интерфейс**;
- **долгое нажатие — назад на BLUETOOTH**;
- подсказок на экране нет.

### 9. GPS
```
module                               on
fix yes
sats 7
```
- строка module: включён/выключен (возможны «off(hw)» при аппаратном выключателе);
- если модуль не найден — «Can't access GPS»;
- **долгое нажатие — вкл/выкл GPS**.

### 10. BEACON (маяк, только при GPS)
Режим и интервал маяка, цель (координаты/нода).
- **долгое нажатие — сменить режим** (0…5, циклически);
- **3 клика — сменить интервал**;
- **4 клика — выключить маяк**.

### 11. SETUP (настройки)
```
Clock                           on
ScreenMode                       2      ← только e-ink
                hold
```
- **долгое нажатие — войти/выйти из режима редактирования**;
- в режиме редактирования: 1 клик — следующая строка, 3 клика — изменить значение.

### 12. SHUTDOWN
Иконка питания + «hibernate: hold».
- **долгое нажатие — выключение** (после отпускания кнопки).

## 5. Интерфейсы связи (что означают ON/OFF)

| Интерфейс | Что это | ON/OFF означает |
|---|---|---|
| **BLE** | Bluetooth LE, подключение телефона с приложением MeshCore | радио BLE включено/выключено; PIN нужен для сопряжения |
| **WiFi** | TCP-сервер по Wi-Fi: **порт 5000** для приложения, **порт 5001** для Home Assistant | оба сервера поднимаются/гасятся одновременно; ON не значит «есть связь» — нужен ещё DHCP-адрес |
| **USB** | Serial-порт (CDC) для приложения с компьютера | обмен по USB разрешён/запрещён |

Особенность: **BLE и Wi-Fi могут работать одновременно**. Пользователь обычно выключает Wi-Fi на улице (экономия) и включает дома.

## 6. Текущие проблемы UX (жалобы пользователя)

1. **Смысл клика меняется**: на обычных экранах 1 клик = «вперёд», а внутри CONNECTIONS 1 клик = «переключить строку». Легко запутаться.
2. **Подэкран невидим**: CONNECTIONS не участвует в листании и не имеет индикации, что это подрежим. Точки страниц продолжают показывать позицию как будто ничего не изменилось.
3. **Подсказки на английском и обрезаны**: «long:connections», «mode: hold», «advert: hold», «3x: profile» — непонятны без документации, занимают место.
4. **Нет обратной связи**: переключение интерфейса не подтверждается ни всплывающим сообщением, ни звуком; визуально строка меняет только ON→OFF.
5. **PIN виден всегда** — на экране BLUETOOTH, даже когда клиент уже подключён; занимает строку.
6. **Дублирование информации**: IP показывается и на FIRST, и раньше на CONNECTIONS (убрали); статус интерфейсов виден и на BLUETOOTH, и в CONNECTIONS в одинаковом виде.
7. **Нет индикации активного соединения** на экране BLUETOOTH (подключён ли телефон/клиент прямо сейчас) — только косвенно через IP на FIRST.
8. **Точки страниц** занимают строку (y=14) и часто конфликтуют с контентом; при большом числе экранов они мелкие и не несут смысла.
9. **Нет названий экранов**: пользователь не понимает, куда он попал (кроме догадки по содержимому). Названия всплывают только как алерты на 800 мс при листании.
10. **Действия спрятаны за долгим нажатием**: почти все функции (advert, poll, scan, профили, LNA, GPS, маяк, выключение) — long press. На однокнопочном устройстве это единственный «второй уровень», но он невидим.
11. **Нет режима «настройки» с меню**: SETUP содержит только Clock (и ScreenMode), остальные параметры (частота, мощность, PIN, язык) недоступны с устройства.
12. **Язык интерфейса**: часть текста английская, хотя прошивка поддерживает кириллицу и русский (в меню не переведено).

## 7. Что нужно от UX-ревью

Предложить **схему юзабилити для однокнопочного устройства с экраном 128×64**:

1. Модель навигации: остаться на линейном листании или перейти к «меню → раздел»? Как показать, что мы внутри подрежима и как из него выйти.
2. Согласованность жестов: как развести «навигация» и «действие», чтобы 1 клик всегда значил одно и то же (или чтобы смена смысла была очевидна).
3. Подсказки и подписи: чем заменить английские «hold:» строки; где ставить название экрана; сколько символов реально использовать.
4. Обратная связь: минимальные визуальные/звуковые подтверждения (вспышка, инверсия строки, короткий бип), не ломающие 1-битный дисплей.
5. Приоритизация функций: что вынести на главный экран, что спрятать; какие экраны можно объединить (например, RADIO + POWER, BLUETOOTH + CONNECTIONS).
6. Индикатор точек: оставить, заменить на «3/11», убрать?
7. Формулировки на русском для всех надписей (с учётом 21 символа в строке size 1).
